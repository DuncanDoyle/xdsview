# Design as built — Phase 9 (Codex)

**Scope:** design.md at 354d765 against the code
**Cross-model:** yes. cli: codex; resolved_model: gpt-6.2-sol; status: ok
**Date:** 2026-11-26

The design mostly matches the exported API and the sampled `00-simple` and `10-policy-levels` JSON. The exceptions affect Snellius’s visibility decisions and kgwctl’s selection, rendering, and payload construction. The changes list at `8d381f6` is incomplete. Review was read-only.

### P1 — Consumer-facing contradictions

- **Candidate completeness, design.md:370.** The design says an `Incomplete` reading at any certainty prevents `Complete`. The code checks only the highest-certainty readings. A lower-certainty incomplete claim can appear in `Candidates` while the input is `covered` and `Complete: true`. A nonempty list containing only `Unknown` claims gets `noEvidence`. [index.go:682](../../../../pkg/envoy/provenance/index.go:682) · [inputs_test.go:106](../../../../pkg/envoy/provenance/inputs_test.go:106)
- **Fail-closed scope, design.md:328–335, 344, 376.** A route-config source block adds its users’ slots and checks placement against their routes, but does not add those routes, backends, or listeners as inputs. An unresolved RDS or scoped-routes use creates no gap of its own. A consumer using an empty `Gaps` result to authorize a view that includes those items would exceed what the index checked. [index.go:506](../../../../pkg/envoy/provenance/index.go:506) · [index.go:553](../../../../pkg/envoy/provenance/index.go:553)
- **Selection and resolution disagree on candidate identity, design.md:260, 376, 418–440.** `Select` uses the highest positive-certainty **claims**, comparing full assertions. Two readings that `Resolve` merges because they differ only in `IndexCertainty`, `Incomplete`, or `Exhaustive` can therefore make selection ambiguous. A single matching claim at `Ambiguous` certainty also goes in `Ambiguous`. [select.go:54](../../../../pkg/adapter/kgateway/select.go:54) · [select.go:96](../../../../pkg/adapter/kgateway/select.go:96) · [index.go:124](../../../../pkg/envoy/provenance/index.go:124)
- **Static-listener selection, design.md:18, 376, 444.** Static listeners are bootstrap and have no `gatewaySource` gap. Their fetched RDS routes receive ordinary claims and can be selected. The exception is already described at lines 337 and 395 but is missing from the selection rule and change summary. [module.go:57](../../../../pkg/adapter/kgateway/module.go:57) · [select.go:53](../../../../pkg/adapter/kgateway/select.go:53)

### P2 — Missing or unclear contract

- **Visibility scope and ownership, design.md:271–278, 328, 372, 385.** `Compose` retains the original snapshot and builds dependency data lazily. Keep that snapshot and nested data in returned claims read-only. Reusing the index with a pruned view still evaluates the original block. `Objects` deduplicates by `(Ref, claim kind)` and includes evidence from outranked claims in scope. Raw `TypedConfig` and per-filter config values are also outside object attribution. The latter are checked by entry and placement. [compose.go:39](../../../../pkg/envoy/provenance/compose.go:39) · [index.go:271](../../../../pkg/envoy/provenance/index.go:271) · [index.go:567](../../../../pkg/envoy/provenance/index.go:567)
- **Gap identity and reasons, design.md:306–319, 339–368.** Inputs merge by the full `Gap` key, so multiple unmatched config keys can become one input. An upstream-only name match can populate `Slot` even though the entry remains `notCoverable`. Empty route sets and weighted-backend per-filter entries also yield `notCoverable`. A rule-3 drop with a non-nil assertion overrides a cover and other reasons on the same key. Nil assertions and rule-4 link drops produce warnings without their own `dropped` input. [index.go:567](../../../../pkg/envoy/provenance/index.go:567) · [index.go:619](../../../../pkg/envoy/provenance/index.go:619) · [index.go:724](../../../../pkg/envoy/provenance/index.go:724) · [compose.go:92](../../../../pkg/envoy/provenance/compose.go:92)
- **What counts as coverage, design.md:339–356.** An `ExtensionSource` can cover a slot with filter-kind evidence alone and no object. Any top resolved candidate marked `Helper` waives the listener-level placement requirement, even when the extension result is ambiguous. “Runs by default” means `!HTTPFilter.Disabled`, including unresolved slots. Placement requires both the link and its record to be at least inferred. - **Claim types and validation, design.md:219–267, 291.** `Ref` is optional and uniqueness applies only to nonempty refs. The assertion table omits the Go field types, especially `ExtensionSource.Extension *model.Ref`, the `Level` constants, and `Opaque{Name, Raw}`. `model.Ref` is group/kind/namespace/name and `Certainty` is an ordered Go integer encoded as text. `Compose` checks evidence presence and object equality. It accepts arbitrary evidence subjects and kinds, so a retained claim can still be excluded by CLI JSON projection. Merged route readings retain the highest `IndexCertainty`.
