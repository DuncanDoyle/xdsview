1. **P1 — TLS verification can be disabled unintentionally.** [portforward.go:199](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/source/kube/portforward.go:199). For HTTPS configs using system roots without explicit TLS options, `rest.TLSConfigFor` returns nil. The new transport supplies that nil alongside a custom dialer; client-go v0.36.2’s `dialURLWithTransport` then sets `InsecureSkipVerify: true`. The previous transport verified certificates. The cancellation test explicitly enables insecure TLS, so it cannot detect this regression.

2. **P1 — Cancellation can return a transport error instead of `context.Canceled`.** [portforward.go:161](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/source/kube/portforward.go:161). Cancelling closes the connection and eventually makes both `ctx.Done()` and `errCh` ready. If `select` chooses `errCh`, it returns the upgrade failure. `spdy.Negotiate` formats its underlying error with `%v`, losing cancellation identity. Thus `errors.Is(err, context.Canceled)` depends on scheduling, contrary to 5.1’s contract.

3. **P1 — Composite classification ignores dynamically configured delegates.** [parser.go:425](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/parser/parser.go:425). An `ExecuteFilterAction` using the valid `dynamic_config` alternative contributes nothing to `compositeDelegate`. With one static ExternalProcessor action and one dynamic action capable of running another type, the filter is nevertheless classified as ExternalProcessor. Unknown delegates must prevent the “every action runs one type” conclusion. Tests cover only static same-type and mixed-type actions.

4. **P2 — #25 remains unresolved through proxies.** [portforward.go:194](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/source/kube/portforward.go:194). When a proxy applies, the connection-close hook is omitted. An unanswered CONNECT or upgrade can therefore retain the connection and forwarder after cancellation; the one-second grace merely stops waiting. The brief documents this exclusion, but it contradicts the phase design’s cleanup guarantee and the completion claim that the long-running UI backend is unblocked.

5. **P2 — Named-rule filtering omits the metadata-backed path.** [filter.go:126](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/filter/filter.go:126). Selection passes only `r.Name` to `routeMatches`, ignoring both metadata and `r.Origin`. The plan explicitly requires matching the metadata-backed `RuleName`. A route identified exactly by metadata or a replacement mapper is still rejected when its Envoy name lacks the expected suffix. CLI annotation also happens after filtering, so replacement mapping cannot help.

6. **P2 — Legacy metadata indices are never decoded.** [kgateway.go:180](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/origin/kgateway.go:180). The v2.4 `rule: "httproute-<name>-<ns>-<r>-<m>"` value is recognised only to avoid treating it as a rule name. Both indices instead come from `r.Name`. Complete legacy metadata with an unrecognised Envoy name consequently returns `Exact` with indices `-1`, despite containing both indices. Corpus tests conceal this dependency because metadata and names always agree.

7. **P3 — Ambiguity’s observable contract is not tested.** [e2e_test.go:193](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/origin/e2e_test.go:193). Without `Known`, tests require only that candidates contain the expected origin. They never require `Ambiguous` certainty or the complete candidate set. An implementation reporting unwarranted `Inferred` certainty could pass and expose guessed origins in the renderer. The planned synthetic ambiguity cases are missing.

8. **P3 — The cancellation test’s timeout can itself hang.** [portforward_test.go:194](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/source/kube/portforward_test.go:194). After the five-second timeout, evaluating `t.Fatalf` blocks on `<-errc`. If connection establishment hangs before the handler receives anything, the test never reaches `Fatalf` or cancellation. This defeats its bounded-failure purpose.

9. **P4 — Successful calls retain cancellation callbacks until the parent context ends.** [portforward.go:220](/Users/ddoyle/Development/claude/kgateway-filterchain-printer-cli-claude/pkg/envoy/source/kube/portforward.go:220). The stop function returned by `context.AfterFunc` is discarded. Closing the reader closes the tunnel but leaves the callback and captured connection registered on a cancellable context. A UI backend repeatedly fetching with its service-lifetime context accumulates these references until shutdown.
