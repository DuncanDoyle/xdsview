I would revise the investigation before approving E14 or adding work to Phase 9. The captured proxy identities undermine the two-replica conclusions, and the proposed version comparison lacks the evidence needed to answer Q1 and Q3 reliably. S5 does support a narrower xdsview addition: identify an active HTTP connection manager whose referenced RDS configuration is absent from a complete Envoy dump. That scenario needs no generic xDS diff. Investigation (`docs/investigations/xds-convergence.md`)

## P1

1. **P1 · correctness · §1.2, S1–S7 — The captures do not establish two independently sampled proxies.** In S1, S2, S4, S5 and S7, the `server_info.json` file labeled `jn2nn` reports `command_line_options.service_node = gw-57f947996b-54p78.demo`. The chart sets that field from the pod name and namespace, and S6’s `jn2nn` response reports `jn2nn.demo`. The capture script reuses local port 19000 without checking which pod answered. The S6 files for the frozen pod are empty. These artifacts leave both-pod acceptance, both-pod rejection, observed replica drift, and recovery within three seconds unverified. S7 shows a later zero controller gauge and an accepted RDS version on the identified proxy. Revalidate each response’s pod and process identity before using these scenarios as E14 acceptance evidence. S1 `jn2nn` server info (local capture, not published) · S6 `jn2nn` server info (local capture, not published) · capture script (local capture, not published) · kgateway deployment (`kgateway/pkg/kgateway/helm/envoy/templates/deployment.yaml:67`)

2. **P1 · architecture · §2 Q1–Q2, §4.1 — Equality of two version strings cannot implement the proposed per-pod, per-type answer.** S5 has two RDS subscriptions on the same identified proxy. `8080` reports `9175…` and `8081` has no accepted version. Envoy invokes named RDS and EDS watches for matching resources, so a subscription readout and a controller-wide type version have different scopes. Also, kgateway’s admin snapshot comes from the embedded cache, which can expose the new version before the corresponding RDS or EDS serving cache is installed. Define which subscriptions are relevant, which controller replica and key cover the pod, and when the samples can be compared. Return `unknown` for incomplete coverage, unproven binding, publish races and held intent. “All observed keys agree” only helps once those keys are shown to cover the sampled pod. Equal versions can then support an acceptance observation, with serving and controller-observed ACK reported separately. S5 stats (local capture, not published) · Envoy watch dispatch (`envoy/source/extensions/config_subscription/grpc/grpc_mux_impl.cc:504`) · kgateway cache install (`kgateway/pkg/kgateway/setup/controlplane.go:189`) · P-009 evidence rules (`kgateway-tooling/program.md:160`)

3. **P1 · correctness · §1.2 S2 and S5, §2 Q3 — A counter increase and a version mismatch cannot identify the currently rejected version.** A watch can reject version B, then remain on A while the controller publishes C. The proposed predicate is still true before the watch has received C. Envoy updates `version_text` on a successful callback and increments `update_rejected` without recording the rejected version in that stat. The SotW mux also dispatches callbacks sequentially, so the claim that RDS was “rejected as a whole” overstates what a response-level NACK proves. S5 establishes that `8081` had no accepted RDS configuration at capture. For Q3, report the observed rejection and mismatch as separate facts and leave current-version rejection `unknown` without correlated evidence. U7 should retain nonce, version and event time for each stream and type, tied to the controller replica and pod identity. An error-free subscription request must remain distinguishable from an ACK. Envoy subscription stats (`envoy/source/extensions/config_subscription/grpc/grpc_subscription_impl.cc:121`) · Envoy xDS protocol (`envoy/docs/root/api-docs/xds_protocol.rst:405`) · U7 (`kgateway-tooling/program.md:241`)

## P2

4. **P2 · architecture · §4.1 — Keep the convergence decision with its consumers and the kgateway snapshot reader outside the Phase 9 provenance module.** D-019 gives the product module a provenance role over Envoy input. A kgateway admin reader and cross-endpoint comparison need controller selection, key coverage, hold state and capture times. Passing only an “intended version” into core discards those facts; passing kgateway’s rules into core couples it to the controller. Let kgwctl own the live join and verdict. Snellius already has a filtered Envoy stats parser, so the draft also needs a named shared consumer before adding a second public parser to xdsview. The missing-RDS observation is the concrete Envoy-config case that earns a core change under D-011. Phase 9 can accommodate that with its dump-coverage work if approved. D-011 (`docs/decisions.md:75`) · D-019 (`docs/decisions.md:153`) · Snellius stats parser (`snellius/pkg/proxystats/parse.go:11`)

5. **P2 · architecture · §4.1 kgwctl row — “Add the controller snapshot” conflicts with the bundle’s explicit collection boundary.** Phase 4 collects controller metrics and can collect proxy admin data. It excludes controller admin because `/snapshots/xds` can contain inline credentials. kgateway’s redactor only replaces entries in the SDS resource array. Define a live diagnostic that emits only the required controller fields, or depend on an upstream endpoint that returns those fields directly. State the offline ceiling explicitly: a bundle can show captured proxy versions, lifecycle and connection signals when available, plus aggregate controller signals. It cannot determine Q1 or confirm Q3 for the current controller version. kgwctl Phase 4 design (`kgwctl/docs/phases/phase-4/design.md:140`) · kgwctl controller-admin boundary (`kgwctl/docs/phases/phase-4/design.md:161`) · kgateway snapshot redaction (`kgateway/pkg/kgateway/admin/xds_snapshot.go:58`)

6. **P2 · correctness · §1.2 S4, §2 Q4 — `update_time` gives the age of the last successful subscription update. It gives no lower bound on how long the proxy has been stale or disconnected.** An unchanged version can remain current for days, then disconnect just before the scrape. `connected_state` establishes the proxy’s connection observation at scrape time. A fresh comparison with controller intent establishes a version mismatch within an observation window. Bound onset using a last-good and first-bad observation or a correlated event. U7’s last ACK and connection timestamps still leave staleness onset unresolved without publication history or a recorded transition. Envoy subscription stats (`envoy/source/extensions/config_subscription/grpc/grpc_subscription_impl.cc:129`) · P-009 time rule (`kgateway-tooling/program.md:166`)

7. **P2 · architecture · §1.2 S5, §2 Q5, §4.1 — Q5 needs separate outcomes for warming, draining and missing configuration.** Envoy dumps warming clusters and draining listeners. The cluster dump has no draining-cluster list, so the proposed inputs cannot identify a stuck draining cluster by name. Snellius 025 sees warming counts on Ready pods. It cannot identify which object remained in that state or find S5’s active HCM with missing RDS. For the core diagnostic, require a complete dump and an explicit unresolved RDS reference at the HCM occurrence. A missing or failed `RoutesConfigDump` parse must yield `unknown`. Use repeated observations of the same resource occurrence for “stuck,” and document the unavailable draining-cluster result.
